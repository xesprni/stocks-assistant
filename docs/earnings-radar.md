# 财报雷达

入口：主导航「财报雷达」，地址 `/earnings-radar`。参考[长桥文章](https://longbridge.cn/zh-CN/topics/44253984)和其中的[工作流说明](https://github.com/flamingo1998/earnings-radar)，在现有服务内用 Python SDK 实现，不依赖 CLI。

## 使用

在设置页连接 Longbridge，并开通所需的美股、期权及日历数据权限。页面支持通过弹窗搜索、勾选当前用户的美股自选（最多 20 个），确认后替换当前扫描清单，取消保留原输入，或输入逗号/空格分隔的美股清单；无后缀的代码按 `.US` 处理，保留 `BRK.B.US` 这类代码。每次最多 20 个标的，默认扫描未来 45 天，可选 30/60/90 天。首次查询需读取近三年日历和日线，可能较慢。

结果包含下一次未公布的财报日（美东日期）、盘前/盘后/时段未确认、EPS 与营收预期、股价和报价时间、ATM 跨式价格、到期日、顺延标识、距到期及财报后天数、历史实际涨跌、样本数、历史绝对波动中位数、比值分档、ATM IV 和 HV30。

HTML 是含内嵌样式和历史图的独立暗色报告，可离线打开。导出由浏览器本地生成。没有后台任务或自动推送；「取消等待」取消前端请求和过期结果更新，已开始的同步 SDK 请求可能继续完成。

## 计算与限制

- 隐含幅度（%）=（Call 最新价 + Put 最新价）÷ 股价 × 100。使用财报日期**之后**最近的期权到期日，选最近的标准 ATM 行权价。最近 ATM 缺少任一有效正数报价时顺延，最多尝试 4 个到期日；不以远价外合约替代 ATM。
- 盘后披露：披露日收盘到下个交易日收盘；盘前披露：前一交易日收盘到披露日收盘。非交易日披露使用下一可用交易日及其之前的收盘。未知时段、没有完整前后价格、前后间隔超过 7 天的事件均排除。
- 日线使用前复权及正常交易时段；保守排除当前美东交易日（即使此时已收盘），避免把未完成的日线纳入一日回报。按事件日期去重，取最近最多 12 次实际涨跌；不承诺总能拿到 12 季。
- 历史中位数使用绝对涨跌幅的数学中位数，偶数样本取两个中间值的均值。中位数为零或没有样本时不生成比值。
- 比值 = 隐含幅度 ÷ 历史绝对波动中位数；`≥1.50` 历史高位区、`≥1.15` 高于常态、`≥0.85` 接近常态、其余低于常态。
- ATM IV 是 Call/Put IV 的均值（两者都可用才计算），按年化百分比显示。HV30 为完整 30 个日对数收益的样本标准差 × √252，日收益不足 30 个时不显示。
- 股价或期权报价时间缺失/超过 3 天会警告。最新成交价可能滞后，且不是可成交的买卖中间价。
- 跨式覆盖至到期日，历史波动只覆盖一个交易日，窗口不同，DTE 及顺延会增加时间价值。比值和标签仅作研究参照，不是套利信号或投资建议。
- 当前仅支持美股。财报安排与预期由长桥返回，可能更新；SDK 没有独立的确认状态字段，本应用不额外声称日期已获公司确认。

## API 与实现

只读扫描：`POST /api/v1/fundamentals/earnings-radar`，需要登录和 `fundamentals:read`。导入自选另外依赖原有 `watchlist:read` 接口。请求：

```json
{"symbols": ["AAPL.US", "MSFT.US"], "days_ahead": 45}
```

固定响应由 `app/schemas/earnings.py` 定义。日期采用 `America/New_York`，抓取时间为 UTC；金额、行权价和跨式成本保留字符串精度，百分比为数值。凭据来自当前用户的有效配置，不读取其他用户的清单。

SDK 5.2 的 `CalendarContext.finance_calendar` 没有暴露 symbol 参数，Python 响应对象也未暴露 `next_date`（虽已列在 `.pyi`）。底层 `/v1/quote/finance_calendar` 则支持 `symbols[]`：财报雷达通过 SDK `HttpClient` 按所选股票过滤，每批最多 10 个，并按[官方 CLI](https://github.com/longbridge/longbridge-terminal/blob/main/src/cli/fundamental.rs)的财报规则同时请求 `types[]=report` 和 `types[]=financial`。不再遍历三年全市场日历，避免密集月份触及分页上限。

日期仍按 30 天分段，每页 `count=100`、`next=later`，沿 `next_date` 继续查询。当某日 `count > 100` 时，即使日期游标已经跳到翌日，也用该日和 `offset=100/200/...` 补取日内分页。`count` 是过滤/合并前的数量，不要求它等于返回的 `infos` 数量；续页为空或完全重复都可能是正常的合并结果，不能据此中断。按递增 offset 读到 count，再在业务层按财报日期和期间去重。每批每段最多 100 个请求，倒退/无进展日期游标仍标记缺口，后续页失败仍保留已取得的数据。

先读取未来窗口，再从最近的历史回溯。日期兼容 `Today 2026.10.09 (EST)` 等本地化标签。HTTP `data_kv[].type` 在边界规范为 `value_type`，用于识别预期/实际数据，不依赖中文事件标题；实际值为 `TBA`、`TBD` 等占位符时仍视为未披露，实际值 `0` 仍表示已披露。披露时段优先读取 `financial_market_time` 的 `before` / `after`，无法识别时再使用 `date_type` 的 `Pre` / `Post`、盘前/盘后等标签，`during` 和未知值仍排除。字段格式已对照[长桥公开财报日历](https://longbridge.com/calendar/report)核验。HTTP 请求复用当前用户的 API Key 或 OAuth 句柄，并显式传入内容语言；每页创建 HTTP 客户端以规避服务端关闭连接后的复用错误。报价连接复用既有 QuoteContext，股价和前复权日线复用 MarketService。

SDK 5.2 的期权链返回 `OptionChainContract` 单合约列表；查询时传入 `standard_only=True`，并按相同到期日、标准属性和行权价配对 Call/Put。SDK 旧期权链地址返回 `404000` 时，通过同一 SDK `HttpClient` 回退到[官方 MCP 使用的查询接口](https://github.com/longbridge/longbridge-mcp/blob/main/src/tools/quote.rs) `POST /quote/options/strikes`，请求体中的 `expiry_date` 为 `YYYYMMDD`。其他错误不触发地址回退；凭据过期仍立即传播。原始合约用具名模型解析，未知标准属性、未知方向及错误到期日不会参与配对。最近 ATM 缺少一边时顺延到下一个到期日，不改选更远的行权价。到期日和期权报价继续复用既有 QuoteContext，不新增行情长连接。

历史、未来日历分别计算连续失败次数，各自连续 3 段失败后停止该窗口并标记缺口；历史请求失败不会阻止未来财报查询，反之亦然。单板块失败保留其余数据并返回问题代码；无权限、停牌、无期权或数据不足不会被补为零。全部标的均无可用数据时返回脱敏的 503，前端显示错误和设置入口，不再展示成功扫描的空卡片。

长桥凭据过期（`401003`）会立即停止扫描并明确提示重新连接或更新 Access Token；即使错误发生在已缓存连接的后续日历、行情或期权请求中也一样。此处使用 503 区分长桥认证失效与应用登录过期。连接创建失败也返回脱敏的 503。日历失败日志只记录日期范围、异常类型和错误码，不记录原始 SDK 错误或凭据。扫描不保存独立数据缓存，避免配置改变后复用旧账户结果。

## 验证

- 回归覆盖全市场第一页不含目标股票、同日续页、异常游标、截断和后续页失败，以及从后续页计算最近 12 次历史反应。
- 后端计算、SDK 替身、权限与用户配置：`uv run pytest tests/test_earnings_radar.py tests/test_earnings_calendar.py tests/test_longbridge_context.py`。
- 完整质量检查：`bash scripts/check_backend.sh`。
- 前端请求竞态、取消、错误重试与导出防注入：`cd frontend && npm test && npm run build`。
- 页面测试使用独立临时服务中的演示数据，检查导入、扫描、缺失/错误状态、HTML 下载与手机布局；真实账户的行情权限及供应商返回数据需在部署环境中验证。
