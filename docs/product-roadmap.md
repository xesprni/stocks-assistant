# Stocks Assistant 产品路线图

> 状态：Phase 0 已实现，Phase 1–2 待验证  
> 基准日期：2026-08-17  
> 规划周期：未来 6 个月  
> 适用范围：产品、设计、前端、后端、数据与 Agent 能力建设

## 1. 产品方向

### 核心判断

Stocks Assistant 当前的问题不是功能数量不足，而是行情、财报、新闻、自选、持仓、Agent、记忆、知识库和调度仍以独立模块存在，没有形成稳定的用户决策闭环：

```text
发现变化 → 核验证据 → 更新投资论点 → 评估组合影响 → 持续监控 → 事后复盘
```

未来 6 个月不以增加页面数量为目标，而以将现有工程能力组织成一套可信、持续、可复现的投研工作流为目标。

### 建议定位

**一个本地优先、私密、持续、可验证的个人投研操作系统。**

产品主承诺：

> 记住用户为什么买，持续检查理由是否仍成立，解释新证据如何影响组合，并让每一步都可验证。

### 首要目标用户

- 覆盖约 10–50 家公司、持有约 5–30 个仓位的严肃个人基本面投资者。
- 重视隐私、长期记忆、自动化和大中华市场语境的技术型投资者。
- 次级用户为小型独立研究团队和家族办公室。

近期不以日内交易者、大型机构合规流程或真实交易执行为首要目标。

### 北极星指标

**每周每位活跃用户完成的可验证投研闭环数（evidence-backed research loops）。**

一次完整闭环定义为：

1. 由材料事件、市场变化或用户问题触发研究；
2. 用户查看至少一条可解析、可回到原文的证据；
3. 用户更新或确认 Thesis / 决策记录；
4. 用户保存下一步监控条件或复核动作。

## 3. 功能优先级

优先级评分用于建立投入顺序，不代表真实用户行为。评分公式为：

```text
战略优先级 = 30% 高频用户价值
           + 25% 差异化
           + 20% 现有架构复用
           + 15% 信任与风险降低
           + 10% 达成价值速度
```

各维度按 1–5 分评估，再换算为 0–100。

| 排名 | 功能方向 | 评分 | 建议阶段 |
|---:|---|---:|---|
| 1 | 统一公司档案与 Thesis OS | 95 | P0，6–12 周 |
| 2 | 证据协议与逐结论引用 | 92 | P0，0–12 周 |
| 3 | 组合感知的事件与条件监控 | 90 | P0，6–12 周 |
| 4 | 引导式上手与研究模板 | 87 | P0，0–6 周 |
| 5 | 组合绩效、风险与归因 | 81 | P1，3–6 个月 |
| 6 | 估值与可比公司实验室 | 73 | P1，3–6 个月 |
| 7 | 股票筛选与发现 | 61 | P2，核心闭环验证后 |
| 8 | 通用回测与策略构建器 | 49 | P2，优先外部集成 |

## 4. 分阶段路线图

以下日期是以 2026-08-17 为起点的建议窗口，实际排期应按团队容量调整。

### Phase 0：修复激活与信任地基

**建议周期：2026-08-17 至 2026-09-28（0–6 周）**

#### 目标

让新用户能够完成配置，并在首次使用中生成一份来源清晰、可保存的研究结果；同时修复会削弱产品可信度的关键断点。

#### Epic 0.1：Agent 数据与证据契约

- 注册并测试 `web_search`，统一搜索、新闻、公告、估值、评级和公司行动的 Agent 工具入口。
- 所有行情与研究工具统一返回：`source`、`source_url`、`published_at`、`as_of`、`fetched_at`、`stale`、`symbol`。
- 定义 `Source`、`Evidence`、`ClaimCitation` 三类核心数据结构。
- 聊天回答区分事实、数据、推断和观点；事实与数字支持点击回到来源。
- 增加引用完整性与来源可解析性的后端测试。

#### Epic 0.2：打通知识库与 Agent RAG

- 统一用户 workspace、knowledge 和 memory 的索引路径规范。
- 知识保存或导入后自动执行增量索引。
- 新增 `knowledge_search` 与 `knowledge_get` 工具，返回文件、行号、页码或段落定位。
- 建立“导入知识 → Agent 检索 → 回答引用”的端到端测试。

#### Epic 0.3：配置与首次使用向导

- 提供模型、Embedding、Longbridge 和通知渠道的连接健康检查。
- 提供可操作错误、依赖关系和测试按钮。
- 配置页在“自动保存”和“显式保存”中选择一种一致机制。
- 提供示例自选、示例组合和至少 3 个研究模板：财报复盘、公司 Deep Dive、持仓风险检查。
- 修正文档中过时的配置与启动说明。

#### Epic 0.4：信息架构与可靠性修复

- 主导航重构为：`Today / Companies / Portfolio / Research / Alerts`。
- 将 Skills、MCP、Tracing、Subagents 和系统设置收纳到 Developer / Admin Center。
- 修复 Market Pulse 在请求失败或无数据时仍可能显示 `LIVE` 的状态问题。
- 修复 Scheduler `started_at` 不遵循注入运行时间的测试回归。
- 增加隐私友好的 opt-in 产品事件埋点。

#### Phase 0 验收标准

- 用户可在一个引导流程中完成全部必要连接检查。
- 导入的用户知识可在 Agent 回答中被检索，并带可解析引用。
- 所有新研究模板的外部事实与数字都有来源和数据时点。
- 行情失败、陈旧和无数据状态不会显示为实时正常。
- 前端生产构建通过，后端测试无已知失败。
- 可以计算首次带引用报告完成时间和激活漏斗。

### Phase 1：交付核心研究闭环

**建议周期：2026-09-29 至 2026-11-09（6–12 周）**

#### 目标

让一家公司从信息对象升级为可长期维护、可监控、可复盘的研究资产。

#### Epic 1.1：Unified Company Workspace

- 新增稳定深链路由：`/security/:symbol/:tab`。
- 在同一标的上下文中组织 Overview、Chart、Financials、Documents、News、AI Research、Thesis、Position 和 Alerts。
- 从自选、组合、新闻和提醒直接深链到对应公司与证据。
- 页面刷新、分享和重新登录后保留标的与研究上下文。

#### Epic 1.2：Thesis OS 与决策日志

- 建立版本化 Thesis Snapshot，至少包含：
  - 商业模式和关键驱动；
  - 关键 KPI；
  - Bull / Base / Bear 情景；
  - 估值假设与预期区间；
  - 催化剂、风险和证伪条件；
  - 信心、时间范围和下次复核日期。
- Chat、财报、新闻和知识内容可一键保存为论点或证据。
- 新证据标记为“支持 / 削弱 / 无关”，并显示 Thesis 相对上个版本的变化。
- 记录人工决策、当时证据和事后结果，支持复盘确认偏误与 Thesis drift。

#### Epic 1.3：第一方材料与财报工作流

- 支持 PDF、公告、filing、transcript 和 slide 摄取，逐步补 OCR。
- 保存材料版本、发布时间、页码/段落以及抓取时间。
- 支持跨期财报、管理层措辞、guidance 和 KPI 变化检测。
- 上线 Earnings Prep / Review 模板：
  - 会前预期与关键问题；
  - 会后数据与措辞变化；
  - 与原 Thesis 的冲突；
  - 需要人工确认的事项。

#### Epic 1.4：组合感知的 Alert Inbox

- 支持价格、成交量、估值、技术指标、新闻、公告、财报、关键词、KPI、评级和组合风险条件。
- 引入事件去重、严重程度、阅读状态、失败重试和送达状态。
- 每条提醒解释：
  - 为什么与用户有关；
  - 影响哪个持仓或自选标的；
  - 影响哪条 Thesis 假设；
  - 当前组合暴露；
  - 建议核查的下一步动作。
- 首页升级为 Daily Research Queue，按重要性展示需要复核的变化。

#### Phase 1 验收标准

- 用户能在单一公司页面完成“阅读证据 → 更新 Thesis → 保存提醒”。
- 每次 Thesis 更新都有版本、来源、修改原因和时间记录。
- 相同事件不会生成重复提醒；提醒可以追溯到来源和触发规则。
- 财报工作流能够展示相对上期和相对原 Thesis 的关键变化。
- 能计算重大事件后的复核延迟、Thesis 更新率和提醒噪声率。

### Phase 2：形成组合智能壁垒

**建议周期：2026-11-10 至 2027-02-17（3–6 个月）**

#### 目标

将“单公司研究”与“整个组合的收益、风险和资源分配”连接起来。

#### Epic 2.1：完整组合账本

- 支持 US、A、H 市场和多币种。
- 记录买入、卖出、调整、分红、费用、税费、现金和 FX 流水。
- 支持 CSV 导入，并优先评估 Longbridge 账户与持仓只读同步。
- 建立可重建的历史持仓与净值序列，避免依赖浏览器本地快照。

#### Epic 2.2：绩效、风险与归因

- 支持 benchmark、TWR、IRR、收益贡献和资金流调整。
- 支持波动、最大回撤、Beta、相关性和集中度。
- 支持行业、国家、币种和可解释因子暴露。
- 支持历史压力情景、假设情景和再平衡比较。
- 所有计算展示数据范围、缺失数据和方法说明。

#### Epic 2.3：Thesis 与组合联动

- 将证伪条件、催化剂和风险映射到持仓权重与组合影响。
- 显示组合中依赖同一宏观假设、行业驱动或币种的隐性集中。
- 当 Thesis 置信度、风险或估值区间变化时，自动生成组合复核任务。
- 保留人工决策权，不输出绝对买卖指令。

#### Epic 2.4：估值与同业实验室

- 在核心闭环证明留存后上线 DCF、reverse DCF、相对估值和同业比较。
- 保存模型假设、数据版本、情景和敏感性结果。
- 支持模型与 Thesis、历史决策和提醒条件联动。

#### Phase 2 验收标准

- 导入交易后可以稳定重建历史净值、仓位和现金流。
- 用户可选择 benchmark，并查看可解释的绩效归因和主要风险暴露。
- 任一重大公司事件都能说明其对应的组合权重和潜在影响路径。
- 估值模型结果可复跑、可比较，并能回到原始数据来源。

## 5. 建议的数据模型

以下对象用于统一未来 API、数据库和前端交互，具体字段在进入开发前通过技术设计确定。

| 对象 | 作用 |
|---|---|
| `SecurityWorkspace` | 连接 symbol、市场、研究材料、Thesis、持仓和提醒 |
| `SourceDocument` | 保存第一方材料、网页、文件、版本和数据时点 |
| `Evidence` | 保存原文片段、页码/段落、结构化数据和来源 |
| `ClaimCitation` | 建立回答或研究结论到 Evidence 的对应关系 |
| `ThesisSnapshot` | 保存版本化投资论点、假设、风险和证伪条件 |
| `DecisionRecord` | 记录用户决策、当时信息、信心和事后结果 |
| `ResearchRun` | 保存模板、输入、工具、模型、数据版本、输出和运行差异 |
| `MonitoringRule` | 定义时间、事件、市场、基本面和组合触发条件 |
| `AlertEvent` | 保存规则命中、严重程度、去重状态、组合影响和处理结果 |
| `PortfolioTransaction` | 统一买卖、分红、费用、税费、现金和 FX 流水 |

## 6. 指标体系

当前仓库未发现完整的产品行为分析，因此第一阶段先建立基线，不预设缺乏依据的绝对目标。

### 激活

- 首次带引用研究报告的完成时间。
- 完成模型、数据源和通知连接检查的比例。
- 完成“首个自选/持仓 + 首条 Thesis + 首条提醒”的比例。

### 信任

- 外部事实与数字的引用覆盖率。
- 引用可解析率和回到原文成功率。
- 陈旧数据率、来源不一致率和事实纠错率。

### 使用与留存

- 每周完成的可验证投研闭环数。
- 每周复核公司数和 Thesis 更新率。
- 重大事件发生后的中位复核延迟。
- 4 周活跃留存。

### 提醒质量

- 提醒打开到查看证据、更新 Thesis 或创建任务的转化率。
- 重复提醒率、噪声关闭率和失效规则比例。
- 调度成功率、重试率和通知送达率。

### 组合价值

- 具备完整交易账本和 benchmark 的组合比例。
- 使用归因、风险、场景和再平衡功能的活跃用户比例。
- 由持仓风险或 Thesis 变化触发的有效复核次数。

### 系统质量

- 工具调用错误率、端到端延迟和单次研究成本。
- 引用完整性、研究模板和财务计算的回归评测通过率。
- 高影响写操作的预览、确认、幂等和审计覆盖率。

## 7. 暂不优先建设

- 普通通用股票聊天框。
- 与现有页面重复的 Dashboard 或新闻聚合。
- 没有组合语境和证据链的 AI 买卖评分。
- 正面复制 TradingView 的全功能图表、Pine 和通用回测生态。
- 在核心闭环验证前建设重型全市场 Screener。
- 在研究可信度和写操作治理完成前接入真实下单。
- 在目标客户仍以个人用户为主时建设复杂多人聊天和审批系统。

回测、筛选和协作等能力优先通过 MCP 或外部集成验证需求，再决定是否自建。

## 8. 需求验证计划

本路线图来自源码、测试、前端旅程和官方竞品能力审计，尚未包含真实留存、营收、访谈和支持工单数据。进入重型功能开发前，应完成：

1. 访谈约 8–12 位符合首要画像的目标用户；
2. 用可点击原型验证 Company Workspace、Thesis Card 和 Alert Inbox；
3. 用人工辅助的 concierge workflow 验证用户是否愿意持续维护 Thesis；
4. 建立激活、引用、提醒与闭环指标基线；
5. 在 Phase 1 结束时，根据真实留存和使用数据重新评审 Phase 2。

重点验证问题：

- 用户最愿意持续维护的是公司 Thesis、事件监控还是组合复盘？
- 港股/A 股/中概股双语材料是否构成真实付费理由？
- 引用需要精确到 URL、页码、段落还是音频时间点？
- 提醒后最有价值的动作是快速解释、更新 Thesis、生成任务还是组合情景？
- 本地优先和自带模型是核心购买理由，还是少数技术用户偏好？

## 9. 依赖与风险

- **数据授权与覆盖**：Longbridge 的真实权限、历史深度和稳定性需要用有效账户验证。
- **第一方材料成本**：filing、公告、transcript、PDF 和 OCR 的覆盖与存储成本可能影响范围。
- **引用质量**：仅保存 URL 不足以形成证据链，需要版本、原文片段和定位信息。
- **告警噪声**：如果缺少去重、严重程度和 Thesis 相关性，主动监控会退化为资讯流。
- **组合计算正确性**：多币种、资金流、分红、费用和缺失价格会显著影响绩效结果。
- **写操作风险**：持仓、任务、文件和未来交易工具必须提供权限、预览、确认、幂等与审计。
- **范围膨胀**：不得用“竞品有此功能”直接替代目标用户和核心闭环验证。
