# 主会话排队输入与运行中补充

主会话提供两种运行中输入。排队输入产生下一轮对话；“补充到当前任务”（steer）修改正在运行的任务。两者都先保存到会话 SQLite，再向界面确认接收。

## 行为约定

| 输入方式 | 执行时机 | 上下文 | 界面状态 |
| --- | --- | --- | --- |
| 排队 | 当前任务成功完成后，按 FIFO 顺序逐条执行 | 从最新会话历史创建新 Agent，沿用用户工作区 | 已排队 → 执行中 → 已完成 |
| 补充到当前任务 | 当前模型调用或整批工具调用结束后，在下一次模型调用前应用 | 沿用当前 Agent、已有工具结果和任务约束 | 等待应用 → 已应用 → 已完成 |

- 运行时输入框保持可编辑，默认选择排队；停止按钮独立于发送按钮。
- 每条排队输入独立产生一轮回复，补充输入不另起运行。补充通常增补原任务，只有用户明确替换目标时才替换。
- “已应用”表示输入已经加入 Agent 上下文，不表示请求的操作已经完成。
- 正在进行的模型调用或工具调用不会被补充输入强制中断。已执行的操作不会自动回滚；已有工具结果可继续复用。
- 停止、失败或服务进程重启后，未执行队列保留并暂停；用户点击“继续队列”恢复。执行中的消息不自动重试，以免重复产生外部副作用。
- 尚未应用的补充只属于提交时指定的运行。该运行结束后，不能悄悄转投下一轮。
- 待处理或失败消息可以移除；已经应用或正在执行的消息不允许当成待处理消息删除。

## 数据与接口

输入记录与会话在同一数据库中，删除或清空会话同时清理相应输入。记录保存消息正文、类型、状态、幂等键、目标运行、实际运行、时间和错误信息。已有会话消息协议兼容，新字段均为附加字段。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/agent/sessions/{session_id}/inputs` | 提交排队或补充输入 |
| `GET /api/v1/agent/sessions/{session_id}/inputs` | 查询输入列表与暂停状态 |
| `DELETE /api/v1/agent/sessions/{session_id}/inputs/{input_id}` | 取消尚未执行或失败的输入 |
| `POST /api/v1/agent/sessions/{session_id}/inputs/resume` | 显式继续暂停队列 |
| `GET /api/v1/agent/sessions/{session_id}` | 同时恢复会话历史、当前运行、输入列表和队列暂停状态 |

提交示例：

```json
{
  "request_id": "client-generated-unique-id",
  "message": "请同时考虑最近一季的现金流变化",
  "mode": "steer",
  "target_run_id": "current-run-id",
  "thinking_enabled": false
}
```

`queue` 不需要 `target_run_id`，思考设置用于将来的新一轮；`steer` 必须精确匹配目标运行，沿用该运行的模型和工具配置。输入列表返回最多最近 100 条，单条消息最多 20,000 字符，同时待处理输入最多 20 条。

`request_id` 标识一次提交：相同请求重试返回同一记录，参数改变返回 409。先检查已有记录，再检查目标运行是否仍接收输入，所以已成功但响应丢失的补充，可以在原运行结束后确认结果。

## 执行边界与持久化

1. 所有主会话运行通过同一运行管理器串行化，同步 `/chat` 与流式 `/stream` 使用一致的互斥规则。
2. 接收、消费补充输入和完成运行共用运行管理器的锁。输入先落库，只有接收成功才显示为待处理。
3. Executor 在模型调用前消费补充。工具调用和工具结果保持完整相邻关系，不在执行工具时插入消息。
4. 模型生成最终回复后，再次原子检查补充：有消息就继续处理；没有消息才关闭补充接收。超过步数上限时，关闭接收并收取已有补充到最后一次总结，避免无限延长运行。
5. 成功落库顺序为原始用户输入、按顺序应用的补充输入、最终助手回复。记忆整理使用包含补充的用户需求，追踪与公开流保存输入状态变化。
6. 正常完成后，后端自动启动下一条排队输入。此过程不依赖浏览器在线；前端收到结束事件后同步会话，并接入下一运行的事件流。

公开 SSE 增加 `input_updated` 事件，`data.input` 为输入记录。页面刷新或断线后以服务端会话详情为准恢复，客户端不会根据本地列表重复提交或重复执行。失败重试保留原幂等键，未确认提交不清空草稿。

## 隔离与恢复范围

- 输入接口仅允许当前用户操作自己的会话；管理员身份不授予跨用户执行工具的能力。
- 排队状态、输入正文和已应用标记持久化；运行管理器和流式重放日志仍使用现有单进程机制。
- 重启恢复只修复持久输入状态并暂停队列，不重建旧 Python 对象、在途工具或旧 SSE 日志。不承诺跨服务进程恢复正在执行的操作。
- 相同用户工作区中的磁盘文件仍可复用，进程内变量不跨运行保留。

## 验证重点

回归覆盖 FIFO 自动接续、普通/流式会话互斥、停止与失败后的暂停、重建存储后的输入恢复、幂等重试、用户归属、容量限制及清空/删除级联；Executor 以线程门控测试模型生成与工具执行期间的补充、结束时竞态、工具结果保留、步数上限和取消行为。前端检查流式接续、按会话隔离的输入状态，并通过 TypeScript/Vite 构建。
